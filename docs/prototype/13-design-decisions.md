| DEC-36 | State form (P1-03). Every space holds a count for every piece flip state and marker side, zero included. A piece with no flip states or a marker with one side uses face key `default`. | DEC-39 | Support scale and level caps are package data. `map.yaml` `supportLevels`: ordered level IDs from Opposition to Support, odd length, middle item is Neutral; range is ±(length - 1) / 2. Schema changes in P1-05 | Fixed ±2 and Office ±1 in core code (game values in code, DEC-02) | A rule value stays data. The UI gets level names (designer decision 2026-10-28) | High |
| DEC-40 | Package loader (P1-05). `readPackageDir` (file I/O) reads the 7 core files and `scenarios/*.yaml` only; files with no schema yet (sequence, actions, cards, victory, assumptions) are not read or hashed until their tasks add them. Every other entry except `scenarios/` and `CHANGELOG.md` gets a V-SCHEMA warning, so a misnamed file is never skipped in silence. `loadPackage` (pure) runs V-SCHEMA, then cross-file checks, then hashes the schema output keyed by file path and compiles the `Ruleset`. New code V-RANGE for scenario values. A bare piece count in a scenario uses the `placedAs` face. Issues carry level, code, file, path, element ID and one sentence. CLI: `make validate DIR=<dir>` (`npm run sim -- validate <dir>`), exit 1 on error | Hash the file bytes (changes on whitespace). Require faces for every flip piece (verbose setup files). Fold range checks into V-REF | Hash identifies rules, not formatting (04 s10.2). Range errors read differently from unknown IDs. Designer approved all choices 2026-10-28 | High |
| DEC-41 | Core effect primitives (P1-07), one file each in `sim/src/engine/core/effects/`, dispatched by `applyEffect`. Track and ordinal ends stop the change and log `PA-04`; empty marker supply logs `PA-09`. Legitimacy overflow is track data: `overflow: {track, costParam}`, compiled to a cost. `count {min, max}` belongs to the card effect schema (P2-05), not to core. The PA-09 Harm warning waits for victory terms (P1-09). An unknown ID throws, because package data is validated on load | Refuse a partly legal effect. Overflow in a Kurdish module or by parameter name in core. Core primitives that open Decisions for `{min, max}` | "Do as much as you can" (04 s5). Game values stay data (DEC-02). Core stays free of Decisions until the apply loop (P1-10). Designer decisions 2026-10-28 | High |
| DEC-42 | Parameter access and literal scan (P1-08). `Ruleset.parameters` holds every `parameters.yaml` value by ID, null for an entry with no value. `param(ruleset, id, kind)` in `engine/core/params.ts` returns a `number`, `string` or `list` and throws on an unknown ID, a missing value or a wrong kind. The scan is ESLint rule `local/no-game-literals` (`sim/eslint/literals.js`), so `make check` runs it. It covers `engine/coin` and `engine/modules`, the handler folders (03 s5), not `engine/core`. It flags every numeric literal other than 0, 1 and 2, fractions and BigInt included (04 s4.5). An exception needs `// literal-ok: <reason>` at the end of the line or alone on the line above. Overflow cost stays compiled to a number (DEC-41) | A Vitest-only scan (not in `make check`). ESLint `no-magic-numbers` (allows any `const` value). Flag only literals above 2 (lets 0.5 through). Scan `engine/core` (RNG constants are not game numbers) | One lint pass for all static rules, as T-ARCH does. A game number in a `const` is still a game number | Medium |
| DEC-43 | Derive, Control and victory terms (P1-09). `victory.yaml` becomes a core file (this replaces its "not read" status in DEC-40) with a schema subset: `scores`, `harmCount` and optional `totals`, each a list of terms that sum. Term and condition shapes are in 04 s8. P1-09 builds the 8 formula terms other than `moduleTerm`, and only the space conditions those terms filter by. Control for N factions: a faction controls a domestic space when its `countsForControl` pieces exceed all other factions' pieces combined (equal to research 03 s6 for two factions). PA-09 Harm warning: `Ruleset.harmMarkers` lists the marker types counted by `harmCount` terms, and `placeMarker` adds `warning: harmSupplyExhausted` to its supply skip. V-VICTORY also needs a threshold for each player faction in each scenario. Margins are score minus the scenario threshold | Term evaluator only, with victory.yaml later. The full condition set now. Exceed each other faction alone. Warnings in `derive` | Scores need a data source (DEC-38). Conditions with no caller wait for their users. The standard COIN rule. The log records the warning when it happens. Designer decisions 2026-10-28 | High |
| DEC-18 | Faction-keyed state. Only the CT sequence model assumes two factions | Two-faction types everywhere | Keeps MOD-3B and MOD-4A possible | High |
| DEC-27 | Node.js 24 LTS minimum (`engines >=24`, `engine-strict`). CI also runs Node 26 | Node 22: maintenance LTS, and its npm 10 runs the `better-sqlite3` gyp build. Node 26 only: Active LTS from 2026-10-28 | Checked 2026-10-27 at P0-01: Node 24.22.1 is LTS (maintenance since 2026-10-20). Node 26 becomes Active LTS 2026-10-28. Sources: https://nodejs.org/dist/index.json, https://github.com/nodejs/Release/blob/main/schedule.json | High |
